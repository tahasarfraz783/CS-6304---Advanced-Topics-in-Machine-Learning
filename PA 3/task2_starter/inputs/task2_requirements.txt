2 Vision-Language Models and Visual Grounding
Introduction and Terminology
A vision-language model (VLM) combines image representations with a language model to generate imageconditioned responses. Connecting two pretrained models requires an interface between their representation spaces
and training that teaches the language model to use the visual information.
A vision encoder converts an image into patch features. A trainable connector maps these features into the language
model’s embedding space, producing continuous visual tokens. These tokens are inserted alongside text embeddings,
allowing the language model to attend to image information when generating its response. Here, a two-layer MLP
connects a frozen SigLIP encoder to Qwen:

Caption alignment trains the connector to make visual features useful for predicting image descriptions. Visual
instruction tuning trains the system to answer image-conditioned questions. LoRA adapters allow the language
model to adapt while its original parameters remain frozen. Training first on captions, then simple visual questions,
and finally natural VQA forms a curriculum. Replay mixes examples from earlier stages into later training.
Visual grounding means that an answer is supported by image evidence. A model can instead exploit language
priors, such as frequently occurring answers to a question type. A complementary pair contains the same question
6
applied to two images with different reference answers. Question wording alone cannot identify both answers. Changing
the image tests whether predictions respond to visual evidence; correctness determines whether that response is useful.
In this task, you will build and train a SigLIP–Qwen VLM through three sequential stages, then investigate grounding
using complementary pairs and image controls. An optional experiment compares 196 and 49 visual tokens.

Data. Prepare three components using COCO 2014 captions and instance annotations and VQAv2 complementary

• COCO captions: select existing image–caption examples for caption alignment and later replay. Use three

• Annotation-derived grounding: write a script to generate template questions and answers from COCO object
annotations. For presence, ask “Does this image contain [object]?” and pair an image with an annotated object
with an image without annotations for that category, giving yes/no targets. For counting, ask “How many [objects]
can you see?” and pair images with different annotated counts between 1 and 4. These questions are generated
programmatically rather than manually written.
• Natural VQAv2: select existing complementary pairs, questions, and human answers. Keep pairs whose
normalized consensus answers differ and have agreement from at least 8 of 10 annotators for each image. Use an
original answer string from the consensus group as the training target; retain all ten human answers for scoring.

Steps
1. Build the Visual Interface. Implement the connector and insert its visual embeddings into the user message
before the question, preserving Qwen’s chat structure. Construct matching labels, attention masks, and position
indices. Check feature shapes, frozen parameter sets, connector gradients, and split isolation. Calibrate connector
output magnitude against text embeddings using training data only, and record the rule and resulting scale.
Logging throughout training. Save training loss, mixture counts, development metrics, and configurations.
Record trainable parameters by stage, runtime, and peak GPU memory, separating feature caching from the
training run. Save raw references, generations, and per-example metrics for evaluation.
2. Caption Alignment. Train only the connector for two passes over the 18,000 caption examples (2,250 updates).
This stage learns an interface between frozen visual features and the language model before adding question-answer
training.
3. Visual Instruction Tuning. Continue for 1,500 updates. For each draw, randomly choose presence with
probability 50%, counting with probability 25%, or caption replay with probability 25%. Train the connector
and newly enabled LoRA adapters, keeping original backbone parameters frozen. Use LoRA rank 16, alpha 32,
dropout 0.05, no trainable biases, and targets q_proj, k_proj, v_proj, and o_proj. This stage introduces explicit
visual questions while retaining caption examples.
Each draw contributes two examples: a complete question pair, or two caption examples for replay. This keeps the
sampling probabilities comparable across components while preserving pairs. Use the seeded random sampler for
both question-training stages; do not enforce exact batch or stage quotas. Repeated sampling of training pools is
allowed.
4. Natural VQA Specialization. Continue the same connector and adapters for 750 updates. For each draw,
randomly choose natural VQAv2 with probability 70%, presence replay with probability 10%, counting replay with
probability 10%, or caption replay with probability 10%. This stage moves from annotation-derived questions to
natural questions and answers.
5. Evaluate Visual Grounding. Apply the development and final evaluation protocols above. Compare correctimage results with complementary, mismatched, and no-image controls, reporting the two suites separately.
Examine whether changes under complementary swaps follow the partner image’s answer or simply produce an
unsupported answer.
6. Analyze Training and Model Behavior. Plot development metrics across stages alongside training loss.
Compare reference likelihood, generated accuracy, and pair-level results across image conditions and question types.
Present complementary images with the shared question, references, and predictions, using a stated selection rule
for illustrative examples. Discuss image use, answer consistency, and the limitations of the observed results.
7. Optional Visual-Token Compression. Repeat the complete recipe with 49 visual tokens, averaging each spatial
2 × 2 block of the 14 × 14 feature grid before the connector. Initialize a new connector and adapters, keeping seed,
data, training budgets, and evaluation unchanged. Compare grounding, accuracy, runtime, and memory with the
196-token run. This experiment is optional.

What to Watch For
• Freezing Qwen’s parameters must still allow gradients to reach the connector. Disabling autograd for its entire
forward pass prevents connector learning.
• COCO annotations can omit objects or contain ambiguous counts. Inspect labels independently of model predictions;
keep evaluation images out of training and replay.
• Swapped-image scores use the original references. Image sensitivity, correctness under the original image, and
following the new image are different measurements.
• No-image inputs also shorten the prefix. Complementary swaps preserve question wording and visual-token count.
• Teacher-forced answer likelihood and free generation measure different behavior.
• Bootstrap complete pairs, preserving their shared question structure. Do not select checkpoints using final-test
results.
Required Evidence
• Learning curves: training loss, development caption loss, answer NLL, and image-swap penalties, with stage
boundaries identified.
• Final results: compact tables for both suites under all four image conditions, including question-type results,
pair diagnostics, reference NLL, correct-image advantages, and pair-bootstrap intervals.
• Qualitative findings: aligned complementary-image examples showing the question, references, and model
responses, with an explanation of example selection and observed behavior.
• Resources: training and generation time, peak GPU memory, and trainable parameters by stage, including
feature-caching costs. Optional compression results may be reported separately.
Research Questions
1. Learning a visual interface. How does the training curriculum affect the model’s ability to describe images and
answer visual questions? What carries over or changes between stages?
2. Grounding and generalization. To what extent do answers depend correctly on visual evidence, and how does
this vary between annotation-derived and natural questions?
3. Measuring image use. How consistent are the conclusions suggested by reference likelihood, generated answers,
pair-level metrics, and qualitative behavior?
4. Capabilities and cost. What capabilities and limitations characterize this VLM, and what computational costs
accompany its training and inference?
